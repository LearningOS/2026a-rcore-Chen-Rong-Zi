# rCore 第四章实验报告

## 1. 功能实现总结

本章实验围绕地址空间与页表机制展开，主要完成了两类功能改造：

- 对 `sys_get_time` 和 `sys_trace` 进行了安全重写。系统调用传入的用户态指针不再被直接解引用，而是通过当前任务的用户页表完成地址翻译与合法性校验，并正确处理跨越页面边界的读写场景，避免直接访问物理内存带来的越界与权限风险。

- 实现了 `sys_mmap` 与 `sys_munmap`，支持匿名内存映射。分配时校验起始地址、长度与权限；维护进程地址空间中的映射区间，检查区间重叠与冲突；回收时解除映射关系并释放对应物理页，保证地址空间的一致性与正确性。

## 2. 问答作业

### 问题 1：SV39 页表页表项的组成与标志位作用

SV39 页表项（PTE）长度为 64 位，主要包含：物理页号（PPN）、保留位、脏位（D）、访问位（A）、全局位（G）、用户位（U）、可执行位（X）、可写位（W）、可读位（R）和有效位（V）。

各标志位作用如下：

- **V（Valid）**：页表项是否有效，V 为 0 时该页表项不合法，访问会触发缺页异常。
- **R/W/X**：分别控制该页是否可读、可写、可执行。
- **U（User）**：控制用户态是否可以访问该页。若 U 为 0，用户态访问会触发异常。
- **G（Global）**：全局映射，通常用于内核页表，切换地址空间时该映射仍保留在 TLB 中。
- **A（Accessed）**：访问位，表示该页是否被访问过，可被操作系统用于页面置换或统计。
- **D（Dirty）**：脏位，表示该页是否被写过，用于判断写回外存的需求。

### 问题 2：缺页相关异常与 Lazy 策略

**可能由缺页导致的异常**

- Instruction page fault：取指时虚拟地址无有效映射或权限不足。
- Load page fault：读数据时发生缺页或权限不足。
- Store/AMO page fault：写数据时发生缺页或权限不足。

**缺页时相关重要寄存器的值**

- `scause`：记录异常原因，用于区分缺页类型。
- `stval`：保存触发缺页的虚拟地址。
- `sepc`：保存发生异常时的指令地址，处理完成后可从中断处恢复。
- `sstatus`：保存中断前的特权级与全局中断使能状态。

**Lazy 策略的好处**

- 减少程序启动时的实际 I/O 和内存分配，加速进程创建与加载。
- 避免一次性分配大量可能不会使用的内存，提高物理内存利用率。
- 简化实现，仅在真正访问时才按需分配页面。

**处理 10G 连续内存页面的 SV39 页表占用估算**

SV39 每页 4KB，页表每级索引占 9 位。10GB 约为 2.5M 个页面。若连续分配，三级页表主要需要：

- 一个根页表（4KB）。
- 若干二级页表。
- 大量三级页表，每页映射 512 个页面，因此三级页表数量约为 2.5M / 512 ≈ 5000 个。

总页表占用数量级约为几十 MB。

**Lazy 策略的实现思路**

初始化时不实际分配物理页，仅在页表中创建无物理映射的项或记录逻辑映射关系。当进程首次访问该虚拟地址时触发缺页异常，操作系统在异常处理中分配物理页、填充页表项，并重新执行触发缺页的指令。

**swap 策略下页面失效在 PTE 上的表现**

当某页被换出到外存后，其对应的页表项有效位 V 会被清零，使该 PTE 失效；下次访问时触发缺页异常，操作系统根据辅助信息从外存换入页面并重新建立映射。

### 问题 3：单页表与双页表

**单页表情况下如何更换页表**

通过写入 `satp` 寄存器切换根页表基址，并刷新 TLB（如执行 `sfence.vma`）使旧映射失效。

**单页表情况下如何控制用户态无法访问内核页面**

在页表项中设置 U 标志位为 0，用户态访问这些页面时会触发异常；同时内核代码数据映射保留在同一页表的高端区域，但仅允许 S 态访问。

**单页表的优势**

- 实现简单，内核与用户态共享同一张页表，无需频繁切换。
- 系统调用与异常处理无需切换页表，开销较小。
- 内核可直接访问用户态地址，无需额外映射或翻译。

**双页表实现下何时需要更换页表**

通常在进入和退出内核态时更换页表：进入内核态时切换到内核页表，退出返回用户态时切换回用户页表。

**若写单页表 OS，何时更换页表**

单页表 OS 不需要在特权级切换时更换页表，只需在进程调度切换、即切换到不同用户进程时更换 `satp` 指向新进程的页表。
